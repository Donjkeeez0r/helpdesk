# HelpDesk — система учёта заявок в техподдержку

**Ссылка на доску:** https://github.com/users/Donjkeeez0r/projects/1/views/1

## 1. Тема и проблема:

**Проблема.** Сотрудники компании сообщают о неполадках (оборудование, ПО, доступы) устно, в мессенджерах и по почте. Заявки теряются, непонятно, кто ими занимается и в каком они статусе, сроки решения не контролируются, а руководитель ИТ-отдела не видит загрузку специалистов.

**Заказчик:** руководитель ИТ-отдела компании.

**Ожидаемый результат:** веб-приложение, в котором заявка проходит путь от создания до закрытия: с назначенным исполнителем, контролем сроков и отчётами для руководителя.

**Ограничения:** срок — один семестр; команда из 4 человек; стек — NestJS, PostgreSQL, React, Docker; работа через браузер, без платных внешних сервисов.

**Условия приёмки:**
1. Заявитель создаёт заявку и видит только свои заявки.
2. Специалист берёт заявку в работу, меняет статус и пишет комментарии.
3. Дедлайн рассчитывается автоматически по приоритету, просроченные заявки выделяются.
4. Все изменения заявки фиксируются в истории.
5. Руководитель получает отчёты по заявкам.

## 2. Аудитория и сценарии:
**Пользователи:** сотрудники компании (заявители), специалисты техподдержки, руководитель ИТ-отдела.

**Ключевые сценарии:**
1. Сотрудник создаёт заявку и отслеживает её статус.
2. Специалист берёт заявку в работу, переписывается с заявителем и закрывает её.
3. Руководитель назначает исполнителя и меняет приоритет заявки.
4. Руководитель просматривает отчёт по просроченным заявкам и загрузке специалистов.

## 3. Границы проекта:

**Входит:** веб-интерфейс, роли и разграничение доступа, жизненный цикл заявки, комментарии, история изменений, контроль просрочки, отчёты.

**Сознательно не входит:**
- приём заявок по email и через Telegram - отдельный крупный объём интеграций;
- база знаний с типовыми решениями;
- мобильное приложение, автоклассификация заявок с помощью ИИ.

## 5. Полномочия:

| Вопрос | Кто решает |
|---|---|
| Определение приоритетов | Руководитель проекта по согласованию с заказчиком |
| Подтверждение завершения проекта | Заказчик — по условиям приёмки |
| Подтверждение завершения задачи | Руководитель проекта после проверки тестировщиком |
| Изменение состава релиза | Руководитель проекта совместно с заказчиком |
| Изменение приоритета задач и багов | Руководитель проекта; баги регистрирует тестировщик и предлагает приоритет |

**Критерий готовности задачи (Definition of Done):** код влит в main, задача проверена тестировщиком, результат соответствует описанию и критерию в issue.
